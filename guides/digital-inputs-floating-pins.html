ESP32 Digital Inputs and Floating Pins

A floating input has no circuit holding it at a defined HIGH or LOW voltage. An unconnected ESP32 pin does not reliably read LOW: leakage, stored charge and nearby electrical interference can affect its reading. Give it a pull resistor or a signal that drives a valid logic level.

📖The Story

digitalRead() reports HIGH or LOW from the voltage at an input. It does not report whether the wire is connected. A disconnected input can therefore look steady or change unexpectedly; neither result makes it a dependable switch input.

Before you start

Board
Classic ESP32-WROOM-32 DevKit with GPIO27 exposed; Arduino board selection: ESP32 Dev Module. Pin numbers are GPIO numbers, not header positions. ESP32-C3/S3 boards need their own pin map.
Software
Arduino IDE 2.x, esp32 by Espressif Systems 3.x (API review baseline 3.3.2). No extra libraries. Serial Monitor: 115200 baud.
Prerequisite
Upload a sketch and open Serial Monitor first. Know the board’s 3.3 V, GND and GPIO27 labels.
Parts
USB data cable, breadboard, jumper wires and a normally open momentary button. No external resistor is needed for the After example on GPIO27.
Expected result
Before: an open INPUT has no guaranteed state, even if it appears steady. After: INPUT_PULLUP reads HIGH released and LOW when the button connects GPIO27 to GND.

ConceptWhy an open input can change

INPUT is high impedance: the pin draws very little current. Without a driven signal or pull resistor, leakage and charge on the wire can move its voltage. Nearby electric fields can couple into a loose lead, which is why moving your hand may change the reading.

Unconnected does not mean grounded. A floating pin might read HIGH, LOW, alternate, or remain at one value during this experiment. There is no required random pattern and no guaranteed LOW. digitalRead() returns a logic state, not an exact voltage measurement.

Wiring Diagram

Follow these steps in order. Unplug USB before you change any wires.

  1. 1

    Before: unplug USB and connect one jumper to GPIO27. Leave its other end unconnected. The illustration shows this floating test lead.

  2. 2

    Upload the Before sketch and set Serial Monitor to 115200 baud. Observe it; a steady value is also possible. Do not treat it as a reliable default.

  3. 3

    With GPIO27 still configured as INPUT, briefly connect the lead to GND (LOW), then to 3.3 V (HIGH), one rail at a time. Keep away from 5 V and adjacent contacts; never join the two rails.

  4. 4

    After: unplug USB. Connect a normally open button between GPIO27 and GND using contacts that only join when pressed. Remove the loose test lead.

  5. 5

    Upload the After sketch, which enables INPUT_PULLUP. Released now reads HIGH; held pressed reads LOW. No external resistor is needed on GPIO27.

Wiring and matching Arduino code

Before: unconnected INPUT

One end of a jumper on GPIO27; the other end open. Upload this complete sketch by itself. This is a demonstration, not wiring to use in a finished project.

floating_input_before.ino 
const int INPUT_PIN = 27;

void setup() {
  Serial.begin(115200);
  pinMode(INPUT_PIN, INPUT);  // No internal pull: leave the test lead open.
}

void loop() {
  Serial.println(digitalRead(INPUT_PIN) == HIGH ? "HIGH" : "LOW");
  delay(250);
}

A steady HIGH or LOW does not disprove floating. The input has no guaranteed state until something defines its voltage.

After: button to GND with INPUT_PULLUP

Disconnect power before rewiring. GPIO27 → normally open button → GND. No connection from the button to 3.3 V; the internal resistor provides the pull-up. Upload this sketch by itself.

floating_input_after.ino 
const int INPUT_PIN = 27;

void setup() {
  Serial.begin(115200);
  pinMode(INPUT_PIN, INPUT_PULLUP);  // Button from GPIO27 to GND.
}

void loop() {
  int state = digitalRead(INPUT_PIN);
  Serial.println(state == LOW ? "LOW - PRESSED" : "HIGH - RELEASED");
  delay(250);
}

The internal pull defines the released state after pinMode() runs. LOW means pressed in this wiring. The 250 ms print interval is not debouncing and can miss quick taps.

OutputExpected Behaviour

Before: HIGH or LOW appears four times per second; it may stay steady or change without touching the wire. Connecting the input to GND should give LOW; connecting it to 3.3 V should give HIGH.

After: HIGH - RELEASED while the button is open, LOW - PRESSED while held closed. Contact bounce may cause brief transitions during a press or release. These are expected behaviors, not recorded hardware measurements.

InternalESP32 Internal Pull-up and Pull-down Resistors

INPUT_PULLUP supplies a weak internal path to HIGH after the pin is configured. The button overrides that path by connecting to GND. INPUT_PULLDOWN provides the opposite default on supported pins; its button would connect to 3.3 V. An external pull resistor works with INPUT instead.

Use GPIO27 for these examples. On classic ESP32, GPIO34–39 are input-only and have no internal pull-up or pull-down: use an external resistor there. Other ESP32 families have different restrictions.

Avoid boot-strapping pins GPIO0, GPIO2, GPIO5, GPIO12 and GPIO15 for this first button circuit: a button or resistor can change the boot configuration. GPIO6–11 are normally connected to flash. Check your board pin map before substituting a GPIO.

!Troubleshooting

Most ESP32 problems are wiring, power, library, or timing issues. Check these first.

  • The floating test always reads HIGH or always LOW

    Likely cause: The input can settle at one level, or the lead may accidentally touch a rail.

    Fix: Check that the lead is open. Do not expect constant flipping. Compare its response when intentionally connected to GND and 3.3 V, then run the pull-up example.

  • After example still changes with the button untouched

    Likely cause: Wrong sketch, unsupported pin, loose connection or an accidental short.

    Fix: Confirm INPUT_PULLUP, GPIO27 and the button-to-GND wiring. Classic GPIO34–39 require external pulls.

  • After example always says PRESSED

    Likely cause: GPIO27 is permanently connected to GND, often through the wrong pair of tactile-switch legs.

    Fix: Disconnect power and identify contacts that only join on a press. Check breadboard rows and continuity.

  • A short tap is missed or a press produces chatter

    Likely cause: Sampling occurs every 250 ms, and mechanical switches bounce.

    Fix: Hold the button for this test. For event counting, use faster sampling and debouncing in the next lessons.

  • Serial output is absent or unreadable

    Likely cause: Wrong port, baud rate, upload or USB cable.

    Fix: Upload to the correct board port, use a data cable and set Serial Monitor to 115200 baud.
