ESP32 DHT11 Reference: Pinout, Wiring and Troubleshooting

📖The Story

A room sensor is a useful first step toward a climate monitor. The DHT11 gives your ESP32 two simple readings, but a reliable build depends on identifying the right pins and letting the sensor work at its own pace.

🧒Explain Like I'm 12

The DHT11 is a small digital sensor that reports how warm and humid the air is. The ESP32 asks it over one data wire, then prints the two readings on your computer.

⚠️

Safety First

  • Unplug the ESP32 before moving wires and check the pin labels on your exact sensor or module.
  • Keep the data pull-up at 3.3 V when it connects directly to an ESP32 GPIO; do not connect a 5 V pulled-up data line to the ESP32.

What the DHT11 measures

The DHT11 is a digital sensor for air temperature and relative humidity. Its controller sends the measurements as a timed digital signal on one bidirectional data line. The ESP32 library decodes that signal; this is not an analog sensor and it does not use the I2C bus.

A DHT11 does not measure barometric pressure, air quality, or altitude. It is useful for basic room, greenhouse, or classroom monitoring, but its update rate is slow and readings depend on placement and the sensor's documented operating conditions. Do not treat it as a precision instrument or as a fast feedback sensor. This reference assumes an actual DHT11, a classic ESP32-WROOM DevKit exposing GPIO4, short breadboard leads, a USB data cable and a documented 3.3 V-compatible sensor/module. Colour alone does not establish the sensor model.

DHT11 is different from DHT22 and AM2302

DHT11 is not the same sensor as DHT22/AM2302. Match the actual part to the library type. A bare four-pin sensor and a three-pin breakout can also have different physical pin orders and power circuitry. Follow the exact part documentation and labels; do not infer the pinout from an illustration.

Identify the sensor pins

A common bare DHT11 package has four pins: VDD/VCC, DATA (sometimes marked SDA), NC (no connection), and GND. On the usual front view with the grille toward you and pins pointing down, those pins are arranged left to right in that order. Check the datasheet for your exact sensor before wiring because package drawings and clone markings can differ.

Three-pin breakout boards typically label the connections with some combination of VCC/+ , DATA/S/OUT, and GND/-. A module's physical pin order is board-specific; follow its silkscreen or wiring diagram rather than copying the bare sensor's left-to-right order. ESP32 DHT11 wiring

  1. Disconnect USB before wiring.
  2. Connect the sensor's VDD/VCC to ESP32 3V3, but only if the exact sensor or module documentation allows a 3.3 V supply.
  3. Connect GND to ESP32 GND.
  4. Connect DATA to GPIO4 for the example code below. Confirm GPIO4 is available on your board; otherwise select a board-appropriate digital GPIO and change DHT_PIN.
  5. Leave the bare sensor's NC pin unconnected.
  6. Check whether DATA already has a pull-up resistor before adding one. Keep the pull-up voltage at 3.3 V for a direct ESP32 connection.

Why the DATA pull-up matters

The DHT11's one-wire data line is released between signals, so it needs a pull-up to return to a HIGH level. A bare sensor normally needs an external resistor between DATA and its supply. The manufacturer shows 5.1 kΩ as a typical pull-up for short connections; Adafruit's example uses 10 kΩ. For this ESP32 example, connect the pull-up to 3.3 V, not 5 V.

Many three-pin modules include a pull-up on the small board, but this is not guaranteed. Check the module documentation or circuit. If a pull-up is already present, an additional resistor may be unnecessary. Never allow a 5 V pull-up to drive an ESP32 GPIO directly. The exact bare-sensor electrical limits and timing are in the manufacturer's DHT11 manual.

Arduino IDE and library setup

Review baseline: Arduino-ESP32 3.3.2, Adafruit DHT sensor library 1.4.6 and Adafruit Unified Sensor 1.1.15. These are reviewed versions, not latest-release claims. Compilation and physical hardware testing were not performed for this update.

The linked DHT11 manual permits 3.3–5.5 V for that revision, but other revisions/modules can specify a higher minimum. Use the direct circuit only for a documented 3.3 V-compatible part, with DATA pulled up to 3.3 V. Otherwise use a documented compatible signal interface; do not simply change this circuit to 5 V. A module regulator does not prove its DATA level is safe.

  1. Install the ESP32 board package and verify you can upload a simple sketch. Follow the ESP32 Arduino IDE setup guide if you have not configured the IDE.
  2. Open Sketch → Include Library → Manage Libraries.
  3. Search for DHT sensor library by Adafruit and install it. Also install Adafruit Unified Sensor if Library Manager does not install it as a dependency.
  4. Select your ESP32 board and port. Match DHT_PIN to the GPIO connected to DATA and keep DHT_TYPE set to DHT11.
  5. Upload the sketch, then open Serial Monitor at 115200 baud.

The library and its current dependencies are documented in the Adafruit DHT sensor library repository. Avoid installing multiple libraries that provide a different DHT.h header; that can cause compile errors or inconsistent behavior.

Complete ESP32 DHT11 Arduino code

dht11_reference.ino 
    #include <Arduino.h>
    #include <DHT.h>

    // Example for a common original ESP32 DevKit. Match this to your wiring.
    const uint8_t DHT_PIN = 4;
    #define DHT_TYPE DHT11

    DHT dht(DHT_PIN, DHT_TYPE);

    void setup() {
      Serial.begin(115200);
      dht.begin();

      // Let the sensor settle before the first measurement.
      delay(6000);
      Serial.println("ESP32 DHT11 reader ready");
    }

    void loop() {
      const float humidity = dht.readHumidity();
      const float temperatureC = dht.readTemperature();

      if (isnan(humidity) || isnan(temperatureC)) {
        Serial.println("Failed to read from DHT sensor; check wiring and settings.");
      } else {
        Serial.print("Temperature: ");
        Serial.print(temperatureC, 1);
        Serial.println(" °C");

        Serial.print("Humidity: ");
        Serial.print(humidity, 1);
        Serial.println(" %");
      }

      // Wait six seconds: more than the linked manual's five-second recommendation.
      delay(6000);
    }

How the code works

  • DHT_PIN: the ESP32 GPIO connected to the sensor's DATA line. If you change the wire, update this constant too.
  • DHT_TYPE: tells the library to use DHT11 timing rather than another DHT model.
  • dht.begin(): initializes the library for the selected sensor and pin.
  • First-read wait and loop delay: wait six seconds at startup and between loop iterations. The DHT11 manual specifies greater than two seconds and recommends more than five seconds between reads. Separately, Adafruit DHT 1.4.6 caches requests made within 2000 ms; the humidity and temperature calls can reuse one transaction. That cache is not the sensor sampling specification.
  • readTemperature(): returns Celsius by default. readTemperature(true) requests Fahrenheit if you need it.
  • readHumidity(): returns relative humidity as a percentage.
  • isnan(): detects an invalid reading so the sketch can report an error instead of printing a misleading number.

Serial Monitor output

Choose 115200 baud in Serial Monitor to match Serial.begin(115200). The following is illustrative output, not recorded hardware measurements; your room's values will differ:

ESP32 DHT11 reader ready
  Temperature: 24.0 °C
  Humidity: 58.0 %

If you see the failure message or nan, the reading did not succeed. Use the checks below before changing the library or repeatedly resetting the board.

DHT11 troubleshooting

Failed readings or NaN

  • Verify DHT_PIN matches the DATA wire and DHT_TYPE is DHT11.
  • Check VCC, GND, common ground, loose breadboard rows, and the sensor/module's pin order.
  • For a bare sensor, add a pull-up from DATA to 3.3 V. For a module, check whether its board already has a pull-up.
  • Keep the six-second startup wait and six-second loop interval in this example.
  • Confirm the IDE installed Adafruit's DHT sensor library and Unified Sensor dependency, and resolve duplicate DHT.h libraries if the compiler reports ambiguity.

Readings look wrong or stay unchanged

  • Confirm the part is DHT11 and DHT_TYPE is DHT11; do not use DHT22 timing for this sensor.
  • Check the exact pin labels and verify the bare sensor or module pin order against its own documentation.
  • Do not power an undocumented module from an assumed voltage, and make sure the DATA pull-up does not expose the ESP32 GPIO to 5 V.
  • Give the sensor time to respond to changes. Avoid touching the sensing grille, breathing directly on it, or placing it beside warm ESP32 components.
  • Read at the supported pace; the library may return a cached earlier reading if asked too soon.

Printed decimal places are formatting, not evidence of 0.1-degree accuracy. Repeated values are normal in steady room conditions; this example is not a calibration test.

Limitations and choosing a different sensor

The DHT11 is a useful learning sensor for basic temperature and humidity logging, but it updates slowly and has no pressure measurement. Choose a BME280 if pressure or pressure-based altitude estimation matters. For faster response, a different sensor may be a better fit; check the model's documented update rate, accuracy, interface, and electrical requirements before choosing it.
