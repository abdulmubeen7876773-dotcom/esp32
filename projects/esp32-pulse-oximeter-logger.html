Pulse Project Mission

Log MAX30102 Raw Red and IR Signals

🧒Explain Like I'm 12

Two LEDs illuminate a target in turn. A detector measures reflected light. The sensor digitizes each channel and stores paired readings in a queue; the ESP32 copies those numbers to Serial Monitor.

For Parents & Teachers

Use only the identified low-voltage board and disconnect USB before rewiring. Do not use this logger for diagnosis, health reassurance, screening or emergency decisions. No skin contact is needed: use a nonconductive card as the optical target. Do not press objects onto or damage the optical window.

BuildWhat You Will Build

A USB Serial CSV logger for paired red/IR optical counts, using a MAX30102 on the documented MAXREFDES117# board and a classic ESP32-WROOM DevKit. It produces no oxygen-saturation, heart-rate or finger-presence result. The historical pulse-oximeter URL is retained.

🔗Wiring

Use the genuine MAXREFDES117# host-side VIN/GND/SDA/SCL pads. This example powers VIN from ESP32 3V3, so the host bus is in the 3.3 V domain; INT is unused. It does not cover an unidentified MAX30102 carrier.

Open wiring diagram full size

  1. 1

    Disconnect USB and confirm the board identity and pad labels against the manufacturer documentation.

  2. 2

    Connect MAXREFDES117# VIN to ESP32 3V3 and GND to GND. Do not connect 3.3 V directly to the bare sensor's 1.8 V VDD.

  3. 3

    Connect host-side SDA to GPIO21 and SCL to GPIO22. Use the reference board's host-level interface, not internal 1.8 V sensor nets. Leave INT unconnected.

  4. 4

    Inspect idle host bus levels and pull-ups for a substituted board before connecting it: ESP32 GPIO is not 5 V tolerant. This wiring is not an endorsement of generic clone modules.

  5. 5

    Install SparkFun MAX3010x Pulse and Proximity Sensor Library version 1.1.2 in Arduino IDE, select the classic ESP32 board/core 3.3.2 and upload the complete sketch below.

  6. 6

    Open Serial Monitor at 115200 baud. Hold a card above the window and log raw counts. No body contact or health interpretation is required.

Circuit Explanation

The selected reference board separates the sensor's 1.8 V core supply from its LED supply and translates the I2C interface to the host side. Powering a generic pad labelled VCC does not prove it includes those circuits. Check the actual board before substitution.

Engineering Explanation

Each value is a dimensionless sensor ADC count, not percent oxygen saturation, BPM, lux or a calibrated blood measurement. LED current, target distance, ambient light and configuration affect the counts. A single IR/red ratio is not a saturation algorithm, and clipping a guessed answer to 70–100 cannot validate it. No such calculation remains. The 411 μs setting selects 18-bit sensor data (nominal digital range 0–262143); full-scale counts indicate clipping, not a valid physiological result.

⌨️Code

Copy into Arduino IDE. Install any libraries noted in the component guides first.

esp32-pulse-oximeter-logger.ino 
// Classic ESP32-WROOM DevKit; Arduino-ESP32 3.3.2.
// MAXREFDES117# (MAX30102); SparkFun MAX3010x library 1.1.2.
// Raw optical counts only: no BPM, oxygen saturation or finger-validity test.
#include <Wire.h>
#include "MAX30105.h"

MAX30105 sensor; // This library class also supports MAX30102 red/IR mode.
bool ready = false;
uint32_t lastDataMs = 0;

void setup() {
  Serial.begin(115200);
  if (!Wire.begin(21, 22)) {
    Serial.println("# ERROR: I2C initialization failed; no samples emitted.");
    return;
  }
  Wire.setTimeOut(50);
  if (!sensor.begin(Wire, I2C_SPEED_STANDARD)) {
    Serial.println("# ERROR: sensor ID not found at 0x57; check power/wiring, then reset.");
    return;
  }
  // LED amplitude, FIFO averaging, red+IR, samples/s, pulse width us, ADC range nA.
  sensor.setup(0x1F, 1, 2, 50, 411, 4096);
  lastDataMs = millis();
  ready = true;
  Serial.println("host_ms,red_counts,ir_counts");
}

void loop() {
  if (!ready) { delay(10); return; }
  sensor.check();
  while (sensor.available()) {
    // Both channels come from the same queued FIFO record.
    uint32_t red = sensor.getFIFORed();
    uint32_t ir = sensor.getFIFOIR();
    sensor.nextSample();
    uint32_t hostMs = millis();
    lastDataMs = hostMs;
    Serial.printf("%lu,%lu,%lu\n", (unsigned long)hostMs,
                  (unsigned long)red, (unsigned long)ir);
  }
  if ((uint32_t)(millis() - lastDataMs) >= 2000) {
    ready = false;
    Serial.println("# ERROR: no fresh FIFO records for 2 s; logging stopped. Inspect, then reset.");
  }
}

Code Explanation

The sketch configures red+IR at 50 sensor records/s with no FIFO averaging, 411 μs integration and ADC range setting 4096 nA. It drains paired FIFO records without an intentional sampling delay. host_ms is the ESP32 receipt timestamp, not an exact optical acquisition timestamp. Failure to identify the device emits an error and no rows. Two seconds without new FIFO records stops logging until reset. The driver does not supply a complete per-record integrity/overflow validity result; this is not lossless acquisition or a verified fault detector. Long host pauses can lose records in its small software buffer. A repeated number or zero is not a finger-validity result.

✨Expected Output

Serial Monitor first shows host_ms,red_counts,ir_counts, then decimal CSV rows from received samples. Values depend on the actual target and setup; no numeric readings or trace are supplied as test evidence. Ambient/background readings are retained. There is no BPM, SpO₂, percent sign or forced plausible measurement. Lines beginning # ERROR are diagnostics, not CSV samples.

🔧Troubleshooting

  • Device not found Power off; check VIN/GND, host SDA/SCL orientation, 3.3 V logic and library version. The shared part ID also cannot distinguish MAX30102 from MAX30105; verify markings/documentation.
  • No fresh FIFO records Logging deliberately stops after the timeout. Inspect wiring and power with USB off, then reset; do not fill the CSV with fabricated zero samples.
  • Counts sit near a rail or change unexpectedly Check target distance, ambient light and selected LED settings. Do not infer SpO₂ or adjust a formula to make numbers look plausible.
  • CSV has time gaps Close other serial programs and avoid adding blocking work. Host timestamps expose receipt gaps, but do not certify continuity or sensor sampling precision.

MistakesCommon Mistakes

  • Using getRed() and getIR() as proof of a calibrated oxygen reading.
  • Substituting an unknown 5 V or 1.8 V bus carrier without checking its schematic.
  • Treating a response at 0x57 as proof of the exact module identity.
  • Blocking the polling loop and assuming all samples were retained.

Testing Checklist

  • Confirm the exact board/pad identity before applying power.
  • Verify host bus voltage before substituting any board.
  • Check that output contains paired raw counts and no medical estimates.
  • Disconnect the sensor with power off, then confirm startup reports failure rather than sample rows.
  • These are checks to perform; no hardware test is recorded.

FAQs

Does this measure blood oxygen or pulse rate?

No. It logs raw red/IR sensor counts only. No saturation or beat algorithm is implemented.

Can I use any MAX30102 module?

No. This supported circuit uses MAXREFDES117#. Other carriers require their own documented power and signal-level review.
