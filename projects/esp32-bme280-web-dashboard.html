ESP32 BME280 Web Dashboard and Live Chart

Read BME280 temperature, humidity and local pressure in a local browser, with five-second sampling, bounded history and visible missing-data gaps.

BuildWhat You Will Build

An ESP32-hosted dashboard with current temperature in °C, relative humidity in %RH and local pressure in hPa. A temperature chart and exact-value table share the same bounded sampling history. The existing weather-station tutorial remains the Serial-first foundation.

SetupBefore You Start

Classic ESP32-WROOM DevKit, Arduino IDE 2.x and Arduino-ESP32 3.3.2 as the review baseline, not a latest-release claim. Select ESP32 Dev Module only for the stated generic WROOM board. Other families need their own pin/radio review. Complete the Serial-only IDE upload first. The complete sketches below were reviewed against documentation; they have not been compiled or tested on physical hardware. One Adafruit BME280 breakout #2652 wired through its labelled header, not a bare chip or unspecified BMP/BME clone. A successful 0x76/0x77 ACK is not device identification. The library also checks chip ID 0x60; that is a compatibility check, not proof of authenticity or measurement accuracy.

👨‍👩‍👧

For Parents & Teachers

USB-powered indoor, low-voltage breadboard demonstration. Unplug USB before rewiring. Keep I2C pull-ups at 3.3 V and do not expose the unprotected board to water or condensation. No alarm, weatherproof enclosure or safety-critical control is implemented.

Parts

  • 📦Classic ESP32-WROOM DevKitUSB data cable; pins 21 and 22 exposed.
  • 📦Adafruit BME280 breakout #2652Documented VIN 3–5 V/level shifting; this build uses 3.3 V VIN. BMP280 is not a substitute.
  • 📦Breadboard and short jumpersNo extra display or memory card.

🔗Wiring

Connect the selected breakout VIN to ESP32 3V3 and GND to GND. SDI (SDA) goes to GPIO21; SCK (SCL) goes to GPIO22. Header names can differ between revisions; identify functions from the exact Adafruit pinout. Leave 3Vo, CS and SDO disconnected for default I2C operation at 0x77. The sketch also tries 0x76 for an intentionally changed address. Its I2C bus is 100 kHz with a 50 ms Wire operation timeout. Do not power a pull-up-equipped unknown module from 5 V and assume its bus is safe.

SetupLibraries and Setup

  • Arduino-ESP32 3.3.2: built-in Wire, WiFi, WebServer and ESP-IDF timer/random APIs.
  • Adafruit BME280 Library 2.3.0, Adafruit Unified Sensor 1.1.15 and Adafruit BusIO 1.17.0. Select these versions in Library Manager.
  • Modern browser with JavaScript, fetch, AbortController and Canvas. No CDN or chart library; raw /samples JSON and Serial remain available.

SettingsConfigure the Example

Replace CHANGE_ME_1234 with your own 8–63 character password. The board creates a local 2.4 GHz AP on channel 6 with one station; it does not use a router, NTP or internet. Sampling starts five seconds after initialization. The board holds up to 60 attempts, about five minutes; reset erases them. Open /samples directly for raw JSON. The page polls only after the preceding request completes, plus five seconds, with a three-second browser request timeout. Background tabs and slow clients can delay updates; this is not a precise acquisition scheduler.

BehaviorControl and Recovery Behavior

ConditionResult
Valid sampleReads chip ID and three compensated values. Finite/in-range checks pass before all three are marked valid; pressure Pa is divided by 100 for hPa.
Missing or bad sampleAdds an unavailable row with null values; the chart breaks its line. Old valid numbers are not substituted as current readings.
Browser disconnect / bad JSONCurrent value is cleared and retained chart/table labelled historical. Next polling cycle attempts recovery without overlapping requests.
History limit / resetOldest attempt is overwritten after 60. A random boot identifier lets the page notice a reboot; no durable storage or UTC timestamps.
Sensor initialization failsDashboard can still serve unavailable attempts. Correct wiring/model and reset; no repeated library initialization loop is added.

bool chipResponds() {
  Wire.beginTransmission(address); Wire.write(0xD0);
  if (Wire.endTransmission(false) != 0) return false;
  if (Wire.requestFrom(address, uint8_t(1)) != 1) return false;
  return Wire.read() == 0x60; // Compatibility check, not proof of authenticity.
}
void sampleSensor() {
  Sample s = {};
  s.seq = ++sequence; s.ms = uint64_t(esp_timer_get_time()) / 1000;
  if (sensorReady && chipResponds()) {
    s.t = bme.readTemperature(); s.rh = bme.readHumidity(); s.hpa = bme.readPressure() / 100.0F;
    s.ok = isfinite(s.t) && isfinite(s.rh) && isfinite(s.hpa) &&
      s.t >= -40 && s.t <= 85 && s.rh >= 0 && s.rh <= 100 && s.hpa >= 300 && s.hpa <= 1100;
  }
  history[head] = s; head = (head + 1) % CAPACITY;
  if (count < CAPACITY) ++count;
  Serial.printf("Attempt %lu: %s\n", (unsigned long)s.seq, s.ok ? "valid" : "unavailable");
}
void sendSamples() {
  String json;
  if (!json.reserve(11000)) { server.send(503,"text/plain","Insufficient memory\n");return; }
  json = "{\"boot\":\"" + bootId + "\",\"now_ms\":" + String((unsigned long long)(esp_timer_get_time()/1000)) + ",\"samples\":[";
  for (size_t i=0; i<count; ++i) {
    const Sample& s = history[(head + CAPACITY - count + i) % CAPACITY];
    if (i) json += ',';
    json += "{\"seq\":" + String(s.seq) + ",\"ms\":" + String((unsigned long long)s.ms) + ",\"ok\":";
    json += s.ok ? "true" : "false";
    if (s.ok) json += ",\"t\":" + String(s.t,2) + ",\"rh\":" + String(s.rh,2) + ",\"hpa\":" + String(s.hpa,2);
    else json += ",\"t\":null,\"rh\":null,\"hpa\":null";
    json += '}';
  }
  json += "]}";
  server.sendHeader("Cache-Control","no-store"); server.send(200,"application/json",json);
}
void setup() {
  Serial.begin(115200); bootId = String(esp_random(),HEX);
  Wire.begin(21,22,100000); Wire.setTimeOut(50);
  // Initialization is a one-time library operation. Reset after correcting a fault.
  for (uint8_t a=0x76; a<=0x77; ++a) {
    address = a;
    if (chipResponds() && bme.begin(a,&Wire)) { sensorReady = true; break; }
  }
  if (sensorReady) {
    bme.setSampling(Adafruit_BME280::MODE_NORMAL,Adafruit_BME280::SAMPLING_X1,
      Adafruit_BME280::SAMPLING_X1,Adafruit_BME280::SAMPLING_X1,
      Adafruit_BME280::FILTER_OFF,Adafruit_BME280::STANDBY_MS_1000);
  }
  Serial.println(sensorReady ? "BME280 initialized; first sample after 5 s" : "No supported BME280; reset after wiring correction");
  server.on("/",HTTP_GET,[](){ server.sendHeader("Cache-Control","no-store");server.send_P(200,"text/html; charset=utf-8",PAGE); });
  server.on("/samples",HTTP_GET,sendSamples);
  server.onNotFound([](){ server.send(404,"text/plain","Not found\n"); });
  if (WiFi.mode(WIFI_AP) && WiFi.softAP("ESP32-BME280",AP_PASSWORD,6,false,1)) {
    server.begin();httpReady=true;Serial.print("Open http://");Serial.println(WiFi.softAPIP());
  } else Serial.println("AP failed; check configuration and reset");
  lastSample = millis();
}
void loop() {
  if (millis()-lastSample >= SAMPLE_MS) { lastSample=millis();sampleSensor(); }
  if (httpReady) server.handleClient();
  delay(1);
}

CodeHow the Code Works

The loop samples independently of HTTP requests and stores a fixed-size ring buffer. GET /samples returns a snapshot in oldest-to-newest order, with a sequence number, a 64-bit monotonic millisecond timestamp since this boot and nulls for invalid readings. GET does not take another measurement. The browser plots temperature only, shows all three quantities in the newest-twelve-attempt table, and breaks connections across invalid rows or timestamp gaps above 7.5 seconds. The chart auto-scales vertically; it does not prove a large physical change. Sensor sampling is nominally every five seconds; page arrival times are not used as sensor timestamps.

✨Expected Output

On a correctly assembled bench the page should show plausible readings, then a growing temperature trend and table. The first few seconds may show no current reading. Older valid history may remain visible during a failure, but its status must identify it as historical. Values depend on the actual environment; no specific readings, calibration accuracy or successful hardware run are claimed here.

🔧Troubleshooting

  • Address responds but library fails Confirm BME280 rather than BMP280, board address configuration, VIN and 3.3 V signal levels. ACK alone does not prove identity.
  • History is present but no current value Read the status and latest sampling attempt. A failed or >10-second-old newest sample is not current; check wiring and reset after power-off correction.
  • Page cannot connect Use the Serial-printed http:// address while connected to the ESP32 AP, not the home router. Check mobile-data/VPN routing.
  • Chart has gaps or stretches Failed samples and >7.5-second time gaps deliberately break the line. Slow synchronous requests/browser scheduling can delay acquisition. No samples are synthesized to hide gaps.
  • Pressure differs from a weather app This is local station pressure in hPa, not sea-level-adjusted pressure. Altitude conversion needs a relevant reference pressure and assumptions; no altitude or forecast calculation is included.
  • Board remains in sensor startup The pinned sensor library performs blocking initialization and calibration-status waits. Wire timeouts do not bound that whole library operation. Remove power, correct the bus/sensor, and reset; no deterministic recovery guarantee is made.

Checks to Perform on Your Build

  • Verify Serial-only BME280 readings before the dashboard.
  • Compare /samples latest attempt with the visible table, units and boot seconds.
  • After several minutes confirm at most 60 attempts remain; invalid rows and timestamp gaps must not be joined with invented points.
  • To test a missing-sensor startup safely, power off, disconnect the sensor, then restart. Do not hot-unplug wires on a powered breadboard.
  • Reboot and check that uptime/history restart; disconnect the browser network and check unavailable/current versus retained-history wording.

DetailsPractical Design Notes

BME280 temperature can be influenced by board heating and enclosure airflow. Range checks reject obvious nonsense; they are not calibration or full I2C fault detection and cannot prove that every plausible result is fresh. Normal-mode sensor conversions run separately from five-second application reads. Supply and pull-up claims apply to the selected breakout; a bare BME280 has different pin/power requirements. RAM history and uptime timestamps are deliberately distinct from a timestamped SD logger. The local server is plain HTTP without user authentication or TLS; the AP password only controls network admission. Do not expose it through a router. Synchronous WebServer and library operations may delay the loop; this is an educational dashboard, not guaranteed real-time monitoring.
