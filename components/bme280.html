BME280 ESP32 Sensor Wiring and Code

Before you start

Board and pins
Classic ESP32-WROOM-32 DevKit, Arduino board: ESP32 Dev Module. This example explicitly uses GPIO21 for SDA and GPIO22 for SCL; these are GPIO numbers, not header positions. Other ESP32 boards need a suitable pin map.
Module assumption
An I2C BME280 breakout whose manufacturer permits 3.3 V at the chosen supply input, with SDA/SCL pulled up to 3.3 V and CS/SDO configured for I2C. Vendor and exact board variant are unspecified; verify its schematic before wiring. This is not a bare-chip build.
Software and libraries
Arduino IDE 2.x; esp32 by Espressif Systems 3.x (API review baseline 3.3.2). Install Adafruit BME280 Library 2.3.0 in Library Manager and accept Adafruit Unified Sensor and Adafruit BusIO dependencies. Wire is included with the core. Serial Monitor: 115200 baud.
Prerequisites and parts
Be able to upload a sketch and open Serial Monitor. Use an ESP32 DevKit, verified 3.3 V BME280 breakout, USB data cable and four short jumper wires; use a breadboard if needed. Begin with only this sensor on the bus.
Expected result
The sketch reports a responding address and chip ID, confirms BME280 initialization, then prints °C, relative humidity (%) and pressure (hPa) about once a second. Numeric examples below are illustrative, not hardware measurements.
Verification status
Reviewed against Espressif, Bosch and Adafruit documentation. Not compiled for an ESP32 or tested on hardware in this update.

BME280 or BMP280?

BME280 measures temperature, relative humidity and air pressure. BMP280 measures temperature and pressure only: it cannot supply humidity. Similar-looking boards and a 0x76/0x77 response do not establish which chip you have.

Bosch specifies chip ID 0x60 at register 0xD0 for BME280, and 0x58 for BMP280. The example checks that register before initializing the BME280 library. A different or unreadable ID calls for a wiring and module-identity check; do not diagnose the sensor from missing humidity alone.

03Pinout

  • VIN / VCC Power input ESP32 3.3 V Use only the supply input documented for your exact board. A VIN label or regulator does not prove 5 V-safe GPIO signals.
  • GND Ground reference ESP32 GND Ground must be shared with the ESP32 and every other I2C device.
  • SDA / SDI I2C data ESP32 GPIO21 SDA may be labeled SDI on a dual-interface board. Confirm the schematic: SDI is I2C data in I2C mode, whereas SDO is not the SDA connection.
  • SCL / SCK I2C clock ESP32 GPIO22 SCL may be labeled SCK on a dual-interface board. Use GPIO22 here; the Wire.begin() pin arguments must match your wiring.
  • SDO Address select or SPI data output GND for 0x76 or VDDIO for 0x77 (chip) The chip’s SDO must not float in I2C mode. A breakout may set it with a resistor or address jumper. Verify that configuration; do not add a conflicting connection.
  • CS / CSB SPI chip select or I2C mode select HIGH at VDDIO for I2C (chip) The breakout may tie CS/CSB HIGH already. Confirm its schematic; a LOW CS selects SPI, and a floating CS is not a defined I2C configuration.

04Wiring Diagram

SDA goes to GPIO21 and SCL to GPIO22 in this sketch. The same chip signals may be labeled SDI and SCK on a board that exposes SPI pins. Follow the module schematic, not its physical pin order or a photograph of another variant.

I2C needs pull-ups on both lines. Many breakouts include them, but this module is unspecified: confirm they connect to 3.3 V. If the module lacks them, add pull-ups sized for the bus’s capacitance, speed and device sink limits. A supply regulator alone does not make 5 V pull-ups safe.

At chip level, CSB must be HIGH for I2C. SDO LOW selects 0x76 and SDO HIGH selects 0x77; SDO must not float. Leave breakout defaults only after checking they establish these levels. Change address jumpers with power disconnected.

  1. 1

    Disconnect USB before wiring. Verify your exact module accepts 3.3 V on the chosen supply pin.

  2. 2

    Connect that input to ESP32 3.3 V, and GND to ESP32 GND.

  3. 3

    Connect SDA/SDI to GPIO21 and SCL/SCK to GPIO22. Confirm these labels from the module schematic.

  4. 4

    Verify CSB is HIGH and SDO has a defined address-select level, through the board’s documented defaults or jumpers. Confirm SDA/SCL pull-ups are to 3.3 V.

  5. 5

    Install the libraries, select ESP32 Dev Module and the correct port, then upload the example.

  6. 6

    Open Serial Monitor at 115200 baud. It probes 0x76 and 0x77, reads chip ID and initializes a responding BME280. If neither responds, use the I2C scanner linked in Continue learning and the checks below.

Wiring and matching Arduino code

Minimal BME280 readout with address and identity checks

Use the four-wire I2C circuit above, with GPIO21 SDA, GPIO22 SCL and verified 3.3 V supply/pull-ups. Upload this complete Arduino sketch.

bme280_esp32_environment_test.ino 
#include <Wire.h>
#include <Adafruit_Sensor.h>
#include <Adafruit_BME280.h>

Adafruit_BME280 bme;
bool sensorReady = false;

int readChipId(uint8_t address) {
  Wire.beginTransmission(address);
  Wire.write(0xD0);  // Bosch chip-ID register
  if (Wire.endTransmission(false) != 0) return -1;
  if (Wire.requestFrom(address, uint8_t(1)) != 1) return -1;
  return Wire.read();
}

void setup() {
  Serial.begin(115200);
  delay(1000);
  if (!Wire.begin(21, 22, 100000)) {
    Serial.println("I2C bus setup failed.");
    return;
  }

  for (uint8_t address = 0x76; address <= 0x77; ++address) {
    Wire.beginTransmission(address);
    if (Wire.endTransmission() != 0) continue;
    Serial.print("I2C response at 0x");
    Serial.println(address, HEX);
    int id = readChipId(address);
    if (id < 0) {
      Serial.println("Chip-ID read failed; check the I2C bus.");
      continue;
    }
    Serial.print("Chip ID: 0x");
    Serial.println(id, HEX);
    if (id != 0x60) {
      Serial.println("Not a BME280 ID (BMP280 is 0x58).");
      continue;
    }
    if (bme.begin(address, &Wire)) {
      sensorReady = true;
      Serial.println("BME280 initialized.");
      break;
    }
    Serial.println("BME280 initialization failed.");
  }
  if (!sensorReady) {
    Serial.println("No initialized BME280. Check wiring, mode and identity.");
  }
}

void loop() {
  if (sensorReady) {
    float temperatureC = bme.readTemperature();
    float humidity = bme.readHumidity();
    float pressureHpa = bme.readPressure() / 100.0F;
    if (isnan(temperatureC) || isnan(humidity) || isnan(pressureHpa)) {
      Serial.println("Invalid reading; check the sensor and bus.");
    } else {
      Serial.print("Temperature: "); Serial.print(temperatureC, 1);
      Serial.print(" C | Humidity: "); Serial.print(humidity, 1);
      Serial.print(" % | Pressure: "); Serial.print(pressureHpa, 1);
      Serial.println(" hPa");
    }
  }
  delay(1000);
}

The two-address probe reports an I2C response separately from BME280 initialization. A response alone does not identify the chip. The register read checks for short/failed transfers; a valid 0x60 is required before bme.begin(). The delay only sets the print interval for this simple local demonstration. If initialization fails, correct the circuit or module identity and reset the ESP32.

OKExpected Output

Set Serial Monitor to 115200 baud. For an initialized BME280, expect I2C response at 0x76 (or 0x77), Chip ID: 0x60 and BME280 initialized.

An illustrative reading is: Temperature: 24.1 C | Humidity: 48.7 % | Pressure: 1012.6 hPa. Your numbers depend on the surroundings; they are not pass/fail target values. Readings print about once a second after initialization.

If you see an address response but no initialization, use the chip-ID message and troubleshooting table. No response at either address suggests a bus, supply, mode or connection problem. A full I2C scan finds other responding addresses but still does not identify a sensor.

Pressure units and altitude estimates

Adafruit readTemperature() returns degrees Celsius; readHumidity() returns relative humidity percent. readPressure() returns pascals (Pa). Divide by 100 for hectopascals (hPa): 100 Pa = 1 hPa = 1 mbar. This is local station pressure, not automatically adjusted to sea level.

A weather service may report sea-level pressure, so comparing that number directly with local pressure is misleading. Compare the same type of pressure or apply an appropriate altitude correction. Watch trends over time rather than treating one number as a rain forecast.

For an optional altitude estimate, bme.readAltitude(1013.25F) returns metres using standard sea-level pressure in hPa. Replace 1013.25 with a current local sea-level reference for a more useful estimate. Weather changes and the assumed atmospheric model introduce error: it is not GPS height or a survey measurement, and a fixed reference can make a stationary sensor appear to move.

The library uses factory calibration coefficients for compensation. Temperature reflects the chip’s temperature and can estimate ambient air temperature when placement is suitable. Keep it away from ESP32/regulator heat, direct sunlight, fingers and condensation; allow airflow and settling time.

06Troubleshooting

ProblemPossible causeSolution
No response at 0x76 or 0x77 Supply or ground missing, wrong SDA/SCL, SPI mode, floating address select, missing pull-ups or damaged module. Disconnect power and verify the module schematic, 3.3 V-compatible supply input, shared GND, GPIO21/22, CSB HIGH, defined SDO and 3.3 V pull-ups. Retry with short wires and only this device; run a full I2C scanner.
Address responds but Chip ID is 0x58 The responding chip identifies as BMP280, which lacks humidity. Use the BMP280 library for that sensor or obtain a verified BME280. Changing 0x76 to 0x77 cannot add humidity.
Chip-ID read failed or a different ID appears A transaction failed, another device occupies the address, or this is a different sensor. Check the short-wire bus and pull-ups, isolate this module, verify its identity and compare its manufacturer documentation. An address ACK alone is not proof of BME280.
ID is 0x60 but initialization fails Intermittent I2C, unstable supply or calibration/register communication trouble. Verify the same Wire bus and pins, power-cycle after correcting connections, then retry with the specified Adafruit library. If failure persists, check the module with its vendor before assuming a software fault.
Missing header or compilation error A required library or the ESP32 board package is missing or the wrong board is selected. Select ESP32 Dev Module with esp32 by Espressif Systems 3.x. Install Adafruit BME280 Library 2.3.0 and its Unified Sensor and BusIO dependencies.
Temperature or humidity is unrealistic Board heat, restricted airflow, condensation, contamination or a bus fault. Move the sensor away from heat, keep it dry and allow airflow. Check successful initialization and wiring; missing humidity by itself does not prove BMP280.
Pressure or optional altitude differs from a weather app Local pressure is compared with sea-level pressure, or the altitude reference is outdated. Compare like pressure units/types. Use current sea-level pressure for readAltitude(); do not treat the result as precise elevation.
Works alone but fails beside an OLED Address collision, wiring problem or combined pull-ups/load affect the bus. Scan with each device alone and then together. Ensure distinct addresses, shared ground and 3.3 V pull-ups; check effective pull resistance and bus capacitance.
Output is unreadable or missing Wrong port, baud or USB cable, or an earlier initialization message was missed. Use a data cable, select the correct port, set 115200 baud and reset to see startup diagnostics.
